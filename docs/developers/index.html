Web Read without a wallet.

Create and fund your key in the browser.

Open the hosted start page, choose Create my key , save the key shown once, then complete card checkout yourself. No terminal is needed to create or fund a key. The key is presented by the service, outside this site.

Create a Web Read key

Already have a key? The same page supports a card top-up. No payment happens until you choose checkout and complete it. You can still use the terminal steps below.

Create a key, fund credits, then read. These commands run in Bash on your own machine. This page does not collect or store your credentials.

Create a workspace key

Free. No email required. The API presents the key once; save it securely. Workspace creation does not include free Web Read credits.

Copy-paste example 
curl --fail-with-body -X POST \
  https://inferrail-cost-gateway.onrender.com/hosted/v1/workspaces
# Save the api_key returned once in a password manager or secret store.
# Load it without putting its value in shell history:
read -rsp 'Workspace key: ' INFERRAIL_API_KEY; echo
export INFERRAIL_API_KEY

Fund it once

One card pack is $10 for 10,000 credits: 5,000 delivered Web Read pages. A person opens the checkout link and pays. No subscription, automatic replenishment or unattended card charge. Check the current live offer before funding.

Copy-paste example 
curl --fail-with-body -X POST \
  'https://inferrail-cost-gateway.onrender.com/hosted/v1/credits/checkout?packs=1' \
  -H "Authorization: Bearer $INFERRAIL_API_KEY"
# Open the returned checkout_url yourself and complete Stripe Checkout.
# This command creates a checkout link; it does not make a payment.

USDC funding is also available at POST /hosted/v1/credits/x402 : $1 for 1,000 credits. Use the funding contract ; a plain curl does not sign payments.

Request a page or PDF

Each delivered result costs 2 credits ($0.002). Refusals cost nothing. Reuse this request ID only to recover this result; choose a new one for a fresh read.

Copy-paste example 
curl --fail-with-body -X POST \
  https://inferrail-cost-gateway.onrender.com/read/credits/v1/page \
  -H "Authorization: Bearer $INFERRAIL_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com/","request_id":"first-read-1"}'

Check the balance

Read credits_remaining from your workspace. An insufficient-credit response is HTTP 402; it explains how to fund, without initiating checkout for you.

Copy-paste example 
curl --fail-with-body \
  https://inferrail-cost-gateway.onrender.com/hosted/v1/workspace \
  -H "Authorization: Bearer $INFERRAIL_API_KEY"

The same API key and balance now pay Package Check at POST /pkg/credits/v1/check and Domain Check at POST /domain/credits/v1/lookup, 2 credits ($0.002) per delivered result. Send the same JSON inputs shown on the evidence-check page. Published SDK 0.3.0 credit tools remain Web Read-only; use direct HTTP for the other two. Credits are a balance, not a per-run spending limit. Never put a key in URLs, source control or client-side application code.

Use your agent’s existing wallet.

Web Read, Package Check, Domain Check and Finder accept direct x402 USDC payments on Base, or MPP on Tempo. You authorize and fund the wallet; the client then signs permitted requests.

Copy-paste example 
curl -i -X POST \
  https://inferrail-cost-gateway.onrender.com/read/v1/page \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com/","request_id":"first-read-1"}'
# HTTP 402: inspect PAYMENT-REQUIRED (x402) and WWW-Authenticate (MPP).
# This unpaid request neither reads the page nor spends funds.
  1. Send the JSON request without a payment to inspect the current offer and input/output schemas.
  2. An x402 client signs the exact Base offer and repeats the same body with PAYMENT-SIGNATURE . An MPP client answers the Tempo challenge with Authorization: Payment <credential> .
  3. HTTP 200 is the paid result. Preserve request identity and payer identity for recovery within the documented window.

Only Base x402 and Tempo MPP were verified live. Do not infer other networks from SDK support. Check price, recipient and network against the current challenge before signing. Other service request examples .

Add Web Read to an AI SDK agent.

Published @inferrail/ai-sdk-tools@0.3.0 supports both payment paths. Use Node.js 22+ with current AI SDK releases (the tools package itself supports Node.js 18+). AI SDK 5+ and Zod 3.25+ are supported peers.

Copy-paste example 
npm install @inferrail/ai-sdk-tools@0.3.0 ai zod @x402/fetch @x402/evm viem

Prepaid Web Read

Copy-paste example 
import { inferrailCreditTools } from "@inferrail/ai-sdk-tools";

const tools = inferrailCreditTools({
  apiKey: process.env.INFERRAIL_API_KEY!,
});
// Pass tools to your AI SDK generateText call.
// readPage and readPages use prepaid Web Read credits.

Wallet-based tools

Copy-paste example 
import { inferrailTools, guardInferrailPrices } from "@inferrail/ai-sdk-tools";
import { wrapFetchWithPayment } from "@x402/fetch";

// client is your configured x402Client; see the complete setup below.
guardInferrailPrices(client);
const tools = inferrailTools({ fetch: wrapFetchWithPayment(fetch, client) });
// readPage, readPages, checkPackages, lookupDomain and findPaidApi.

creditsFetch(apiKey) is also exported for server-side HTTP requests. Credit-mode readPages uses individual reads: successful pages are charged even if others fail. Direct wallet batches are all-or-nothing. Published 0.3.0 can obscure whole-batch authentication errors; inspect each failure and do not rely on the improved 0.3.2 source until published.

Paid tools in your MCP client.

Claude Desktop

Download Web Read extension 0.3.0 . Configure your API key or funded wallet and daily spending limit. The extension uses secure client configuration for secrets.

Claude Code, Cursor & stdio clients

Run the published package locally. API-key mode exposes read_page and read_pages . Wallet mode also offers check_packages and lookup_domain ; the AI SDK’s Finder tool is not a local MCP tool.

Copy-paste example 
{
  "mcpServers": {
    "inferrail-paid-tools": {
      "command": "npx",
      "args": ["-y", "@inferrail/ai-sdk-tools@0.3.0"],
      "env": {
        "INFERRAIL_API_KEY": "YOUR_WORKSPACE_KEY",
        "INFERRAIL_MAX_USD_PER_DAY": "0.10"
      }
    }
  }
}

Treat your client config as a secret; use its secure secret mechanism where available. In wallet mode, replace INFERRAIL_API_KEY with INFERRAIL_WALLET_KEY for a wallet you control holding USDC on Base. Never configure a wallet you have not authorized the client to spend from.

The local server defaults to $0.10 per UTC day and refuses purchases past its local limit. This limit applies to that server’s accounting, not all clients sharing a wallet or workspace; the daily record persists locally across restarts in INFERRAIL_STATE_DIR (default ~/.inferrail). Keep the balance small enough for your use case.

Different product: Python’s inferrail mcp is read-only gateway reporting with get_spend and get_health . It does not purchase pages or execute paid tools. Read-only MCP setup .

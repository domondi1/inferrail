A specific delivery contract.

API key & credits

Credits are held while the source is read, billed on successful extraction and released on failure. The response reports the credits charged. Insufficient funds return HTTP 402 before a read.

Direct wallet payments

x402 on Base and MPP on Tempo verify authorization first and settle only after successful extraction. HTTP 200 is the paid result. A refused source does not settle the payment.

Recovery

Retry with the same URL and request_id , and the same wallet or workspace identity, within 10 minutes. The stored result is returned without a second charge. Use a new request ID for a fresh read. Preserve the same ordered URL list for a direct batch.

Retention & integrity

Delivered content is temporarily stored for recovery. Wallet recovery uses a 10-minute window; stored credit results are expired lazily on later recovery lookups, so this is not a precise deletion-time promise. Accounting records remain. A SHA-256 identifies returned content; it does not certify the source’s truth. Source metadata may be absent or wrong.

Know which sources to choose.

Supported

  • Public HTTP(S) addresses on ports 80/443, including redirects.
  • HTML, plain text, Markdown and text-layer PDFs.
  • Source metadata exactly as declared; missing fields stay null or empty.

Boundaries

  • robots.txt is respected. No JavaScript execution, bot-check bypass, login or paywall bypass.
  • HTML/text: 2 MB. PDF: 5 MB, first 50 pages. No OCR for scanned documents.
  • Up to 3 redirects; fetch timeout 15 seconds per request. PDF parsing has separate bounded processing.
  • No universal coverage or completeness guarantee. Some JavaScript pages yield thin text; inspect the returned content.

HTTP 422 describes invalid or unreadable sources. Target 5xx, fetch failures and timeouts may be retried later (502/504); do not blindly retry a permanent refusal. Production error contract .

Less markup in your model’s context.

The published 20-URL benchmark delivered 17 responses and observed roughly 9× lower estimated token counts at the median versus raw HTML. Estimates use characters ÷ 4, not a model tokenizer. One delivered response was a thin JavaScript shell and is explicitly a miss. This is a small extraction sample, not a guarantee of complete content or workflow savings.

For agents that pay

One agent job, from price to receipt

An agent buys three web pages for one job. It pays only for what it gets, a refused page costs nothing, and matching retries can recover a paid result within 10 minutes.

Simulation Example data. No payment is made.

  1. ○ Priced

    The agent checks the price

    It asks Web Read for news.example/a and gets HTTP 402: the price, the network and where to pay. Nothing is held yet. 

    402  $0.002 · USDC on Base (x402) or Tempo (MPP)
  2. ◐ Authorized

    It authorizes the payment

    The purchase fits the job's budget, so the agent signs a payment for exactly $0.002 and repeats the request. The money hasn't moved. 

    POST /read/v1/page  PAYMENT-SIGNATURE: …
  3. ● Settled

    Extracted, then settled

    Web Read extracts readable content first, settles the authorized payment, then sends the paid result and receipt. A lost HTTP response can be recovered. 

    200  412 words · sha256 3f1c…e09a · settled
  4. ⊘ Refused, not charged

    A refused page costs nothing

    The next page is blocked by the site's robots.txt. Web Read refuses it, and the signed payment is never settled. 

    422  disallowed_by_robots_txt · charged: false
  5. ↺ Recovered

    Recover a lost response

    The agent buys news.example/c , but the response is lost. Within 10 minutes, the same wallet retries the same URL with the same request_id and a new signature, gets the page it paid for, and the new signature is never settled. 

    200  recovered: true · no second charge
  6. ≡ Receipt

    A receipt for the whole job

    Every purchase has a payment reference and a content hash the agent can check, so the job's cost reconciles to what it received.
